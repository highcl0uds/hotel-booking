# ADR-0006. JWT (HS256) с проверкой и в Gateway, и в каждом сервисе

## Контекст

По ТЗ токены выпускает Booking Service: регистрация и вход, срок жизни 1 час. Каждый сервис проверяет JWT самостоятельно (Resource Server). Роли: USER и ADMIN. Внутренние эндпойнты саги должны быть недоступны пользователям.

## Решение

- Подпись **HS256** общим секретом из переменной окружения `JWT_SECRET`. Длина секрета не меньше 256 бит, проверяется при старте.
  - Claims: `sub` (имя), `uid`, `roles`, `iss`, `iat`, `exp`.
  - Токены выпускает `JwtTokenFactory` (Nimbus из Spring Security), сторонняя JWT-библиотека не нужна.
- **Gateway** — реактивный resource server: без валидного токена пропускаются только регистрация, вход, документация и health. Токен передаётся сервисам без изменений.
- **Сервисы** проверяют подпись, срок и издателя ещё раз (общая автоконфигурация в модуле `common`). Роли проверяются на методах через `@PreAuthorize`.
  - Иерархия ролей: `ADMIN > USER`.
  - Проверка «только свои брони» сделана в сервисном слое: чужая бронь → `403`.
- **Внутренние вызовы** Booking → Hotel идут со служебным токеном (роль `INTERNAL`, срок 1 минута). Токен выпускается на каждый запрос, общего изменяемого состояния нет.
  - `INTERNAL` не входит в иерархию ролей, поэтому пользовательский или админский токен на `confirm-availability`/`release` получает `403`.
  - Gateway эти маршруты не публикует вовсе: `404` ещё до проверки токена.
- Ответы 401 и 403 приходят в формате `ErrorDto`, с заголовком `WWW-Authenticate: Bearer`.

## Плюсы и минусы

- (+) Компрометация Gateway или ошибка в его маршрутах не открывает сервисы: они защищены сами.
- (+) Проверка токена не требует сетевых вызовов.
- (−) Выданный токен нельзя отозвать: смена роли или удаление пользователя полностью вступают в силу, когда истечёт его токен (не позже чем через час). Создание брони дополнительно проверяет, что пользователь ещё существует (`401 UNKNOWN_USER`). Если нужен немедленный отзыв, понадобятся короткие токены с refresh или список отозванных `jti`.
- (−) Общий симметричный секрет: любой сервис с ним технически может выпустить токен. В продакшене стоит перейти на RS256 и JWKS (`/.well-known/jwks.json` в Booking Service). Остальной код при этом не меняется.
